# @hjdd14/dsh-together · 工作中小游戏

Agent 每次要**修改文件**时，Host 会把它拦在这一步，Web 界面弹出一个小游戏；用户达到门槛后，那次工具调用才继续执行。通关后进入可配置的冷却窗口，冷却期内的修改不再弹游戏。

## 它拦什么

| 入口 | 说明 |
|---|---|
| `tools/pre-execute` | 每一次工具调用都会经过这里（包括 PTC 子调用）。写文件类工具（`write` `edit` `apply_patch` `ops_*` 等）直接拦；shell 类工具（`bash` `pwsh` `terminal` `run_code`）只在命令看起来会写文件时拦（`>`、`rm`、`sed -i`、`Set-Content` 等）。 |
| 冷却 | 通关后按 `cooldownSeconds` 静默；同一会话的并发写共享一局游戏，不会连弹。 |
| 无浏览器 | `pauseWhenNoClient` 打开时，没有在线浏览器就直接放行，避免把会话永久卡住。 |
| 兜底 | 同一局连续 3 次基础设施故障（游戏崩溃 / 超时）会自动放行并留日志；插件卸载、会话关闭、回合取消都会让等待立即结束，绝不悬空。 |

拦截发生在**派发之前**，所以被拦的工具调用不会产生任何副作用；用户不通过，它就一直在等。

## 设置

设置 → 「工作中小游戏」。改完即生效（不需要重启 Host，也不会重启插件）：

- **冷却时间**：通关后的免打扰秒数，0 = 每次修改都要玩。
- **难度**：轻松 ×0.7 / 标准 ×1 / 严格 ×1.3，作用在游戏门槛上。
- **一次挑战几局**：1–3 局连玩，全部通过才放行。
- **单局时限**：超时不判通过，只提示重来或换一局。
- **拦截写文件的命令**、**额外拦截的工具名**（正则）、**放行的路径**（正则）。
- **参与的游戏包 / 禁用的单个游戏**：98 个游戏里挑。
- **显示「测试放行」后门**：在浮层和设置页显示一个直接放行按钮（默认开）。它**不记分数、不产生冷却**，用于调试或某局实在过不去时解卡，胜率统计里单独计入 `testPasses`。
- **试玩一局**：不影响 Agent 放行，用来先试试手感。

页面切到后台时，本局计时自动暂停，不会因为你离开而白烧一局时限。

设置存在 `<profile>/dsh-together.json`（原子写）。刻意**不用** Cordis `Config`：普通 Config 改动会重启插件，把正在等待的 gate promise 变成永久挂起。

## 3D 游戏（立体 3D 包，8 个）

中型 3D 游戏跑在**自建的紧凑 WebGL1 渲染层**上（`client-src/core.js` 的 `tgCreateGl3d`：透视相机、盒子/平面/球、一束方向光、深度测试，约 200 行），游戏侧只写：

```js
api.gl3d.camera({ eye: [0, 6, 12], target: [0, 1, 0] })
api.gl3d.draw(api.gl3d.mesh('box'), { x, y, z, ry, s: 1.2 }, '#4f8ef7')
```

**为什么不用 three.js**：这个客户端模块表只解析平台 seed（`react`）、已物化模块和 boot graph 里的包行，`dsh.client.external` 是"按包名排依赖"而不是"加载任意 URL"，本机 `node_modules` 里也没有 three；把 three 的 UMD 塞进工厂还要模拟 `module/exports/global` 并且多背 ~600 KB。自建层零依赖、能被冒烟测试桩驱动，做塔防/打砖块/滚珠/叠塔这类中型玩法够用。跑酷另有更便宜的「伪 3D」：`api.depth.project(x,y,z)` 在 2D canvas 上做模式 7 透视（`tunneldash` 用的就是它）。

无 WebGL 的环境会显示「此环境不可用」并按一次故障上报，3 次自动放行兜底，不会卡住调用。

## 拦截器自检

`GET /x-together/self-check`（设置页顶部那个小圆点也读它）报告 `listenerSeen` / `enabled` / `eligibleGames` / `recent`。存在理由：插件被反复热重载后 `tools/pre-execute` 监听有可能没挂上，那时**所有写操作会静默放行**；有自检就能一眼分清"没挂上"和"挂了但放行"。

监听挂在**根作用域**（`ctx.root`）上：分发走的是 `scopeTarget(tools, agent)`，事件只向"发射方 + 祖先"传播，插件自己的 fiber 与 `ctx.inject(['tools'], …)` 得到的子 fiber 都不在那条链上——这是之前"重启后拦截静默失效"的真正原因。根作用域是所有上下文的祖先，因此不会漏。

设置页还有两个按钮：**验证拦截**（让插件自己发起一次真实写文件，被拦下就说明链路通）和**看一个 3D 游戏**（强制抽 3D 包，用来检查立体画面）。

## 单独看 3D 游戏

`GET /x-together/play3d?game=<id>` 会返回一个**空页面**，里面只有同一个游戏、同一个 WebGL 层和一份 `api` 垫片，适合在全屏下检查立体画面（也绕开 DSH 里其他插件的弹窗）：

```
http://127.0.0.1:<port>/x-together/play3d?game=stack3d
http://127.0.0.1:<port>/x-together/play3d?game=td3d
http://127.0.0.1:<port>/x-together/play3d?game=brick3d
```

8 个 3D 游戏：`td3d` `brick3d` `maze3d` `stack3d` `snake3d` `runner3d` `race3d` `cubehunt`。

## 结构

```
index.js            Host 入口：接线 pre-execute、会话清理、路由、卸载兜底
host/gate.js        状态机（无 Cordis 依赖，可单测）：挑战、冷却、放行、失败兜底
host/classifier.js  哪些工具/命令算「修改」
host/settings.js    设置文件原子读写 + 归一化
host/catalog.js     门槛计算、抽题
host/routes.js      /x-together/{state,catalog,complete,switch,fail,settings,preview,eligibility}
client-src/core.js  引擎 + 浮层 + 设置页（构建进 lib/client.js）
client-src/games/   98 个游戏，一个文件一个游戏（每个都有粒子/连击/抖动/缓动等「手感层」）
shared/catalog.js   唯一的游戏目录（id / pack / 门槛 / 名称 / 一句话说明 / 操作方式）
build.mjs           拼装 lib/client.js
test/               gate / 98 游戏冒烟 / 产物集成 三组测试
```

浏览器与 Host 之间没有生成的 Remote 命名空间（本包是普通脚本 bundle），所以用同源的 `/x-together/*` JSON 路由：浮层在有挑战时 500ms 轮询、空闲 2.5s、页面隐藏 5s。每条路由都用 `ctx.connection.requestRejection` 校验来源。

## 加一个游戏

1. 在 `shared/catalog.js` 里加一条：`{ id, pack, goal: ['score'|'count'|'survive', target], zh, en, bz, be, c }`。
2. 在 `client-src/games/<pack>/<id>.js` 写一个普通脚本：只调用一次 `defineGame({ id, create })`，`create(api)` 返回 `{ update(dt), draw(g) }`。接口全表见 `client-src/games/API.md`。
3. `node build.mjs && TG_PACK=<pack> node --test test/games.smoke.test.mjs`。

## 验证

```bash
node build.mjs                 # 拼装 lib/client.js（会做语法与 id 校验）
node --test test/gate.test.mjs
node --test test/games.smoke.test.mjs   # 98 个游戏 × 600 帧随机输入

```

## 已知边界

- 只在 Web 界面生效：没有 `webServer` 的组合（headless/CLI）里插件不会激活。
- 不拦截 shell 里绕过命令文本的写入（例如脚本内部写文件），也不做防作弊——门槛是给自己用的。
- 统计与最高分只在内存里，Host 重启清零。
- 没有音效（不引入音频资源）；节奏类游戏靠视觉节拍。
